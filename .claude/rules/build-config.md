# Build and Configuration Guidelines

## Worker Build Is Part of the Build

`src/providers/worker-string.ts` is auto-generated by `scripts/build-worker.js`. The main `build` script must run `build:worker` first. Never edit or commit `worker-string.ts` — always regenerate it.

```json
"scripts": {
  "build": "npm run build:worker && npm run build:lib",
  "build:worker": "node scripts/build-worker.js",
  "build:lib": "tsc"
}
```

If you change anything in `src/providers/worker.ts` or under `src/utils/tasks/`, run `npm run build:worker` to keep the generated file in sync.

## Chrome Extension Build Mode

Use `NODE_ENV` to select Webpack mode. Never release an extension built in `development` mode — it includes source maps and skips minification.

```js
// chrome-extension/webpack.config.js
module.exports = {
  mode: process.env.NODE_ENV === 'production' ? 'production' : 'development',
  devtool: process.env.NODE_ENV === 'production' ? false : 'source-map',
  optimization: {
    minimize: process.env.NODE_ENV === 'production',
  },
};
```

Build for release: `NODE_ENV=production npx webpack --config chrome-extension/webpack.config.js`

## Vite — Separate Heavy Modules into Chunks

The browser-ui bundles AI model utilities and WebGPU workers that are large. Define `manualChunks` in `browser-ui/vite.config.ts` to keep the main chunk small and enable parallel loading.

```ts
export default defineConfig({
  plugins: [react()],
  envPrefix: 'VITE_',
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'ai-utils': ['./src/utils/tasks/ai/text-generation'],
          'media-utils': ['./src/utils/media'],
        },
      },
    },
  },
});
```

## TypeScript — Use Real Types

`tsconfig.json` has `strict: true`. Work with the type system rather than around it. Replace `any` with a concrete interface or `unknown` with narrowing.

```ts
// Avoid:
async function processTask(data: any): Promise<any>

// Use explicit types:
async function processTask(data: TaskData): Promise<TaskResult>
```

Type aliases that resolve to `any` (e.g. `type TaskResult = any`) add nothing — define a real shape instead.

## Use const and let

All variable declarations use `const` (preferred) or `let`. Never use `var`.

## Avoid new Promise(async ...)

The `new Promise(async (resolve, reject) => ...)` pattern silently drops unhandled rejections from the async body. Return the async function's promise directly.

```ts
// Avoid:
return new Promise(async (resolve, reject) => {
  const result = await doWork();
  resolve(result);
});

// Use:
return doWork();
```

## Check for Existing Utilities Before Adding New Ones

Before writing a new utility or provider, check `src/utils/` for something that already covers it. Duplicate logic in multiple locations diverges silently over time. Consolidate and import from one place.
